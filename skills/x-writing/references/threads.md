# Xスレッド設計

スレッドは「長いから分割する」ためだけに使わない。
**順番に読むことで理解や納得が深まる内容**に使う。

## 1. スレッド向き

- 時系列が重要な体験
- 原因 → 結果 → 学びの順が必要
- 複数の具体例を並べる必要がある
- 反論や例外まで扱わないと誤解される
- 一つの投稿では情報を削りすぎる

一つの主張だけで成立するなら単発を優先する。

## 2. 基本構造

### 1投稿目

- 違和感、結論、場面のどれかで始める
- 何の話か分かる
- 中身のない「スレッドです」は避ける
- すべての結論を隠して釣らない

### 中盤

- 1投稿につき一つの役割
- 具体例、理由、反例、転換などを割り当てる
- 各投稿だけ切り出しても最低限意味が通る
- 前投稿の言い換えで水増ししない

### 最後

- 一番残したい結論か、小さな具体へ戻る
- 毎回「どう思いますか？」で終えない
- noteへの誘導があるなら内容を出した後に自然に置く

## 3. 分割ルール

段落の途中で機械的に切らない。
意味の役割ごとに切る。

悪い分割:

- 文字数だけで等分
- 3語だけの“パンチ投稿”を挿入
- 「続きは↓」だけの投稿
- 1/10〜10/10を埋めるための水増し

番号は読みやすさが上がる場合だけ使う。

## 4. リズム

投稿ごとの長さを人工的に長短交互へ揃えない。
内容に必要な長さを使う。

短い投稿が自然に効くことはあるが、AIっぽさを消す目的で短文を差し込まない。

## 5. note記事からのスレッド化

記事の見出しをそのまま1投稿ずつ割り当てない。

まず記事の論理を次の役割へ再整理する。

- 入口
- 背景
- 具体
- 反例・条件
- 結論

不要な役割は削る。
必要なら同じnote記事から、単発投稿版とスレッド版を両方作れるようにする。
