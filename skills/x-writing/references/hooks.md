# Xフック設計

フックは「煽るための一文」ではない。
**本文の中にすでにある一番強い材料を、最初に見える形へ出す作業**として扱う。

## 1. 先に素材を掘る

次の候補を元素材から拾う。

- 一番意外な事実・観察
- 一番具体的な数字・場面・固有名詞
- 一番強い違和感や意見
- 一番共感されやすい日常の瞬間
- 一番しょうもないけど効いているユーモア
- 読後に残る結論

元素材にない強い材料を、フックのために作らない。

## 2. 同じ文の言い換えを量産しない

候補は最低5案ほど内部生成し、違う仕組みを混ぜる。

使える入口:

1. **違和感型** — 常識と少しズレる観察
2. **具体型** — 数字、場面、対象を前に出す
3. **体験型** — 実際の経験・観察から始める
4. **損失・負担型** — 本当に存在するコストや面倒を示す
5. **共感型** — 読者が経験しやすい瞬間から入る
6. **物語型** — 結果ではなく緊張が始まる位置から入る
7. **問い型** — 本当に自然な疑問がある場合だけ使う

毎回「逆張り」「数字」「質問」を入れる必要はない。

## 3. 選び方

候補ごとに0〜2点で点検する。

- **Truth**: 本文がその約束を回収できるか
- **Specificity**: 抽象語だけでなく具体があるか
- **Standalone**: 1行目だけでも話題が伝わるか
- **Voice**: `style-profile.md` の本人らしさがあるか
- **Pull**: 次の一文を読みたくなる未解決が自然に残るか

合計点だけで機械的に決めない。上位2案を比較し、本文との相性で最終決定する。

## 4. 禁止

- 本文より強い断定
- 「知らないと損」「99%が知らない」など根拠のない煽り
- 元素材にない数字や実績
- 「結論から言うと」の機械的使用
- 毎回の「炎上覚悟」「 unpopular opinion 」型
- 内容が薄いのに好奇心だけ煽るクリックベイト

## 5. noteから作る場合

noteのタイトルを短くするだけでは弱い。
記事全体から一番強い一要素を選び、X用に入口を作り直す。

- 記事の結論を全部書く案
- 途中の違和感だけ切り出す案
- 体験や数字だけ切り出す案
- ユーモアだけ切り出す案

を比較し、同じ記事から違うX投稿が作れる状態を目指す。
