# x-writing

X向けの文章を作る。

目的は「短くすること」ではない。
**長文の中から、タイムライン上で単独でも立つ一個の観察・違和感・主張を抜き出し、書き手の声を残したまま圧縮すること**である。

note記事から作る場合も、本文の要約をそのまま140字前後へ縮めない。
noteとXでは読む状況が違うため、X用に冒頭、情報量、オチ、余白を組み直す。

## 0. 必ず併用するもの

作業開始時に、存在すれば次を読む。

1. `../../style-profile.md`
   - ユーザー固有の読点、話し言葉、自虐、ユーモア、避ける癖を最優先する。
2. `../natural-japanese/SKILL.md`
   - 語順、主述、直訳調、AI臭、不自然な日本語を点検する。
3. note記事から再構成する場合は元記事そのもの
   - 元記事にない体験、数字、感情、会話を足さない。

優先順位は、
**ユーザーの今回の指示 > root style-profile.md > x-writing > natural-japaneseの一般則**。

## 1. モード

### write
テーマやメモからX向けポストを新規作成する。

### repurpose
note、ブログ、長文、授業メモなどからX向けに再構成する。
単なる要約ではなく「Xで一投稿として読める芯」を選ぶ。

### thread
一投稿に詰め込まず、複数ポストへ自然に分ける。
各ポスト単体でも意味が通じるようにする。

### audit
既存ポストを書き換えず、弱い冒頭、説明過多、AI臭、誇張、事実リスク、誘導の不自然さを点検する。

## 2. 標準出力

ユーザー指定がなければ、`write` と `repurpose` では4案を出す。

1. **主張型**
   - いちばん伝えたい考えを前に出す。
   - 一文目だけで続きを読みたくなるようにする。
2. **体験型**
   - ユーザーが実際に話した経験や観察がある場合だけ使う。
   - 経験を盛らない。数字も元データにあるものだけ使う。
3. **ユーモア型**
   - 元素材にあるズレ、自虐、日常的な可笑しさを使う。
   - 奇抜な比喩を新しく量産しない。
4. **note誘導型**
   - 記事の結論を全部書かず、読む理由が残る位置で止める。
   - note URLが与えられていない場合はURLを捏造しない。
   - 「続きはnoteで」だけの中身のない投稿にしない。

4案は同じ文の語尾違いにしない。焦点、入り口、温度を変える。

## 3. 長さ

短文ポストを既定とする。

- 日本語中心なら、標準投稿の上限ぎりぎりまで詰めず、**おおむね110〜130字程度を第一目安**にする。
- 英数字、URL、絵文字、全角文字などの扱いで実際のカウントが変わりうるため、厳密な投稿可否が必要なときはXの現行仕様を確認する。
- ユーザーがX Premiumの長文投稿を明示した場合だけ長文モードを使う。
- 情報が多すぎるなら、文字を削って意味を壊すより `thread` を選ぶ。

短いことより、読み終わったときに一つ残ることを優先する。

## 4. 冒頭

最初の一文に、次のどれか一つを置く。

- 違和感
- 身も蓋もない結論
- 具体的な観察
- 実体験から出た短い断定
- 少し笑えるズレ

避ける:

- 「今回は〜について解説します」
- 「知らないと損」
- 「結論から言うと」の乱用
- 「有益なので保存推奨」
- 「〜な人に届け」
- 本文より大げさな煽り

## 5. X向けのリズム

- 読点で間を大量に作らない。
- 一文を長くしすぎないが、短文を機械的に3連打しない。
- 改行は意味の切れ目にだけ使う。
- 「AではなくBだ」を毎回フックにしない。
- 絵文字はユーザー指定がなければ原則0〜1個。なくてよい。
- ハッシュタグは原則0〜2個。記事側のタグを全部流用しない。
- `#英語学習 #勉強法 #英語` のような一般タグの大量列挙で文字数を消費しない。

## 6. noteからXへ変換するとき

記事全体を均等に圧縮しない。
まず記事から次を抽出する。

- いちばん書き手らしい一文
- 読者が反応しそうな違和感
- 一番具体的な経験・数字
- 一番しょうもないけど効いているユーモア
- 記事を読み終えたときに残る結論

そのうち1〜2個だけを1投稿に使う。

note誘導型では、記事の結論を100%言い切らない。ただし釣りにもしない。
投稿だけ読んでも価値があり、記事を読むともう一段深くなる状態を目指す。

## 7. 事実とハルシネーション

次を厳守する。

- ユーザーが言っていない指導人数、実績、資格、失敗談を足さない。
- 研究、制度、数字、現在の仕様などは必要なら確認する。
- 確認できない事実は断定を弱めるか削る。
- note本文の誇張表現をさらに強くしない。
- 引用元がない名言や「研究で証明されている」を作らない。

## 8. AI臭を避ける

特に避けるもの:

- 「本質は〜」の多用
- 「たった1つ」など根拠のない限定
- 3項目の箇条書きを毎回使う
- 最後に毎回教訓を置く
- 自己啓発っぽい決め台詞
- 不自然な共感要求
- 「どう思いますか？」を毎回付ける

問いかけは本当に会話を生みたいときだけ使う。

## 9. thread

スレッドは、1投稿目に結論を全部詰めない。
ただし「続きは次へ」だけで情報を引き延ばさない。

- 1投稿目: 入口となる違和感・結論
- 中盤: 具体例、背景、反例
- 最終: 記事の芯か小さな余韻

番号表記 `1/4` などは、ユーザーが望む場合か読みやすさが上がる場合だけ使う。

## 10. 出力形式

標準では次の順に出す。

```markdown
# X投稿案

## 1. 主張型
...

## 2. 体験型
...

## 3. ユーモア型
...

## 4. note誘導型
...
```

note URLが与えられている場合だけ、note誘導型に実URLを入れる。

## 11. 最終チェック

出力前に確認する。

1. 元素材にない体験や数字を足していないか。
2. 一文目だけで何の話か分かるか。
3. noteの要約になっていないか。
4. 4案が本当に違う入口になっているか。
5. 煽りが本文より強くなっていないか。
6. 読点が増えすぎていないか。
7. ハッシュタグと絵文字が邪魔していないか。
8. URLを捏造していないか。
9. 投稿単体でも最低限の価値があるか。
10. 書き手本人が言いそうな温度か。
