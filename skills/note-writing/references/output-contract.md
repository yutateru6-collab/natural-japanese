# 標準出力契約

ユーザーが別形式を指定しない場合に使う。
本文だけ、タイトルだけなど明示された場合は、その指定を優先する。

## 1. タイトル候補

3案。
同じ内容の言い換えにせず、焦点を変える。

```markdown
# タイトル候補

1. ...
2. ...
3. ...
```

## 2. 冒頭3行候補

3案。各案は意図した改行で3行。

```markdown
# 冒頭3行候補

## A案
1行目
2行目
3行目

## B案
...

## C案
...
```

## 3. 編集済み本文

最も合う冒頭を組み込む。
ユーザー指定がなければ1499字以内。

- 太字は必要な箇所だけ
- 見出しは必要なときだけ
- 1文1段落を機械的に続けない
- スマホで読める段落長にする

```markdown
# 編集済み本文

本文
```

## 4. ハッシュタグ候補

5〜7個を1行で。

```markdown
# ハッシュタグ候補

#英語学習 #英単語 ...
```

## 5. 関連記事への導線文

3案。
実在記事が不明なら必ず「仮タイトル」と書く。
URLは作らない。

```markdown
# 関連記事への導線文

1. 導線文
   「記事タイトル」（仮タイトル）
2. ...
3. ...
```

## 6. 見出し画像の方向性

3案。
各案に次を含める。

- 画像案のタイトル
- どんな絵か
- なぜこの記事に合うか

```markdown
# 見出し画像の方向性

## 画像案1
画像案のタイトル：...
どんな絵か：...
なぜこの記事に合うか：...
```

## 7. 画像生成プロンプト

3案のうち最も本文に合う1案を完成プロンプトにする。

```markdown
# 画像生成プロンプト

【画像生成プロンプト】
...
```

標準条件:

- note向け横長
- 生活感
- 少しユーモア
- 説明しすぎない
- 文字なし
- ロゴなし
- AI的な過剰光沢を避ける

## 8. 編集上の注意点

3つだけ。
すでに直した欠点を「まだ問題」として書かない。
褒めるための項目を置かない。

```markdown
# 編集上の注意点

1. ...
2. ...
3. ...
```

## auditモード

書き換えず、次を返す。

1. 総合点 /100
2. P0 / P1 / P2
3. 一番強い点
4. 一番弱い点
5. 優先修正3つ
6. 必要なら修正版の一部例

ユーザーが「書き直して」と言っていない限り全文を勝手にリライトしない。

## style-learnモード

次を返す。

1. 観察した文章
2. 文体の傾向
3. 強く再現すべき特徴
4. 避けるべき特徴
5. root `style-profile.md` への更新案

サンプルが3本未満なら、傾向の確度が低いと明記する。
